# Agentic GTM Factory

3-stage AI-powered Go-To-Market operating system: S1 Strategy/Discovery → S2 Market Research/Scoring → S3 3-Channel Outreach, with an M3 Intelligence Loop that feeds engagement, intent, feedback, and attribution back into the ICP.

## Run & Operate

- API:  `python3 -m uvicorn main:app --host 0.0.0.0 --port $PORT` (in `artifacts/api-server/`)
- Web:  `vite --host 0.0.0.0` (in `artifacts/app/`)
- Seed: `python3 artifacts/api-server/seed.py`
- Required env: `DATABASE_URL`, `ENCRYPTION_KEY`, `AI_INTEGRATIONS_OPENAI_BASE_URL`, `AI_INTEGRATIONS_OPENAI_API_KEY`
- All third-party tool keys (SerpAPI, Apollo, Clay, Instantly) are managed in-app via Settings — encrypted with Fernet in the `app_settings` table.

## Stack

- Backend: Python 3.11 + FastAPI + SQLAlchemy 2 + psycopg3 + pgvector (sse-starlette for streaming).
- AI: Replit OpenAI Integrations proxy (gpt-4o-mini). No real embeddings API — pgvector uses deterministic SHA-based pseudo-embeddings (see `app/llm.py`).
- Frontend: React 18 + Vite + Tailwind v4 + shadcn/ui + TanStack Query + Wouter (no codegen — direct fetch).
- DB: Replit PostgreSQL with `pgvector` extension.

## Where things live

- `artifacts/api-server/` — FastAPI service (no Node code anywhere).
  - `main.py` — app factory + router mounting under `/api`.
  - `app/db.py` — all SQLAlchemy models. Source of truth for schema.
  - `app/agents/` — S1 strategy SSE pipeline, S2 lead/signal/scoring/pattern, S3 outreach generator, SDR copilot, M3 intent/qualify/loop-back.
  - `app/services/settings_service.py` — encrypted in-DB integration keys.
  - `app/services/clients.py` — thin HTTP wrappers, return None when no key set.
  - `app/routes/` — one router per domain (settings, strategies, accounts, contacts, signals, sequences, copilot, intelligence, dashboard).
  - `seed.py` — minimal Acme demo strategy + accounts/contacts/signals.
- `artifacts/app/` — React frontend (built by design subagent).
- `lib/api-spec/` and `lib/api-client-react/` — legacy Node codegen scaffolding, unused by this app.

## Architecture decisions

- Replit OpenAI proxy does not expose embeddings; `llm.deterministic_embedding()` produces a normalised 384-dim hash-based vector so pgvector clustering still works for the demo.
- All external integrations are optional: each `*_search` returns `None` if no key is configured, and the agent falls back to AI-generated demo data flagged with `is_demo`/`source: "ai_demo"` so the UI can label it.
- S1 generation is exposed as Server-Sent Events so the frontend can render a live pipeline.
- Lead scoring is a weighted composite (ICP fit 30% + signals 40% + engagement 30%) with a small boost when learned `pattern_clusters` exist for the strategy.

## Product

- Strategy & Discovery (S1): ICP, persona matrix, problem map, NAICS segmentation, stakeholder graph, use-case library — all generated by the LLM.
- Market Research & Scoring (S2): TAM/SAM/SOM, competitor research, lead discovery (Apollo or AI demo), buying-signal detection (SerpAPI or AI demo), composite scoring, pattern recognition.
- 3-Channel Outreach (S3): persona-aware sequencer (email/LinkedIn/call), deliverability check, launch (Instantly or simulated).
- M3 Intelligence Loop: engagement events, intent classification, feedback with auto-extracted sentiment+themes, attribution summary, MQL/SQL/Nurture qualification, and ICP loop-back suggestions with one-click apply.
- SDR Copilot: per-strategy "next best action" feed prioritised by signal recency and reply detection.

## Gotchas

- **No auth.** This is a single-operator console; all `/api/*` routes are unauthenticated. Add Replit Auth or Clerk before exposing externally.
- S1 SSE rejects re-runs while `status == "generating"` to prevent interleaved writes.
- LLM JSON failures surface as `{"_error": ...}` and are **not** persisted into strategy fields; the stage event still fires so the UI can show the previous payload.
- Lead discovery is now idempotent — re-running matches by email and `(account_id, full_name)` so no duplicates accumulate.
- Frontend uses `BASE_URL` from Vite for both API calls and Wouter routing; if the artifact previewPath ever changes, both will follow automatically.
